У владельца нет доступа Freedom Pay. Код не может выпустить merchant ID,
платёжный ключ или заменить одобрение провайдера. Нет подтверждённого внешнего
платежа, sandbox-прогона или банковского списания. Готовность .env не доказывает
правильность ключей — это отдельно проверяется у провайдера.

Следующий внешний шаг
--------------------
Обратиться в Freedom Pay Kazakhstan через официальный сайт/менеджера и запросить:
«Нужен тестовый доступ Merchant API для учебного сервиса доставки еды JetFood
на Django: KZT, hosted payment page, тестовые merchant ID и payment secret,
тестовые карты, уведомления о платеже и частичные возвраты».
https://docs.freedompay.kz/overview-741636m0
Не отправляйте секретные значения в чат, не добавляйте их в frontend или .env.example.

Когда тестовые ключи будут получены
---------------------------------
Все команды выполняются из C:\Users\tald1\Desktop\JetFood.

1. Создайте/войдите в свой аккаунт ngrok, получите его authtoken:
   https://dashboard.ngrok.com/get-started/your-authtoken
   Это ДРУГОЙ секрет: он не является платёжным ключом Freedom Pay.

2. Запустите в отдельном PowerShell:
   powershell -NoProfile -ExecutionPolicy RemoteSigned -File .\scripts\start-payment-tunnel.ps1
   При первом запуске скрипт попросит ngrok authtoken скрытым вводом.
   Он сохранится в игнорируемом .jetfood-tools/ngrok.yml, а не в исходниках.
   Скрипт откроет туннель к Django на 8000. Оставьте терминал открытым.
   Скопируйте показанный HTTPS-адрес БЕЗ пути, например https://your-domain.ngrok-free.app.
   Используйте туннель только для локальной sandbox-проверки, после неё Ctrl+C.

3. В другом терминале:
   py manage.py setup_test_payments

   Введите последовательно:
   - выданный тестовый merchant ID;
   - тестовый платёжный ключ (ввод скрыт);
   - HTTPS-адрес туннеля без /api и других путей.
   Команда сохранит значения в .env и принудительно оставит TEST mode=1.
   Другие параметры .env сохраняются. Невалидный ввод не перезаписывает файл.
   Команда требует обычного интерактивного терминала; ввод секрета через pipe отключён.

4. Проверьте:
   py manage.py check_payments

   Нужен Local configuration: READY. Это означает только заполненные корректные
   локальные параметры; credentials_verified остаётся false до внешней проверки.
   В кабинете провайдера, если требуется, укажите выведенный callback:
   https://ВАШ-ДОМЕН/api/payments/result.php

5. Остановите старый Django через Ctrl+C и запустите заново:
   py manage.py runserver

   В отдельном терминале:
   cd frontend
   npm.cmd start

6. На http://localhost:4200 добавьте блюдо, адрес и online payment.
   Убедитесь в надписи TEST, перейдите на Freedom Pay и используйте ТОЛЬКО
   выданные тестовые карты. После возвращения проверьте серверный статус оплаты.
   При задержке уведомления:
   py manage.py reconcile_payments
   Не считайте redirect/success доказательством списания.

Примечания
----------
- Файл .env.example остаётся шаблоном; реальные значения вводятся в .env.
- Явные переменные процесса имеют приоритет над .env. Если ранее в этом PowerShell
  задавались старые FREEDOMPAY_* или PAYMENTS_* через $env:, откройте новый терминал
  перед запуском Django, чтобы они не перекрывали новые значения файла.
- Если HTTPS-адрес туннеля поменялся, повторите setup_test_payments и перезапустите Django.
- Дополнительные разрешённые Django-хосты можно указать в DJANGO_ALLOWED_HOSTS через запятую.
- Для новой машины зависимость автозагрузки: py -m pip install -r requirements-payments.txt.
- Для замены ngrok authtoken запустите скрипт с -Configure.
- Пока внешнего доступа нет, выбирайте оплату наличными. Фиктивная успешная карточная
  оплата вместо Freedom Pay не включалась.
