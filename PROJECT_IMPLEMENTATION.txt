TASK 2: System Analysis / Role Updates Based on Analysis
------------------------------------------------------------------

Team Member: Person 2
Implementation Location: analytics/views.py

A. SYSTEM ANALYSIS
   - File: analytics/views.py
   - Function: system_analysis(request)
   - Endpoint: GET /api/analytics/analysis/
   
   - Analysis Features:
     1. Order Volume per User
        * Aggregates order count and total spent per customer
        * Identifies high-volume customers (threshold: >20 orders)
     
     2. Delivery Performance
        * Calculates average delivery time per delivery person
        * Tracks delivery duration metrics
     
     3. Active Users (Last 30 Days)
        * Counts users with last_login within 30 days
        * User engagement tracking
     
     4. Revenue Trends (Last 7 Days)
        * Daily revenue aggregation
        * Daily order count
        * Time-series data for charts

B. ROLE UPDATE SUGGESTIONS
   - File: analytics/views.py
   - Function: system_analysis() returns role_update_suggestions
   
   - Logic:
     * Users with >20 orders suggested for "manager" role
     * Analyzes user behavior patterns
     * Returns list of suggested role changes with reasons

C. APPLY ROLE UPDATES
   - File: analytics/views.py
   - Function: apply_role_updates(request)
   - Endpoint: POST /api/analytics/apply-role-updates/
   - Access: Admin only
   
   - Implementation:
     * Accepts list of role updates
     * Validates role permissions
     * Updates user roles in database
     * Returns confirmation of applied changes

TASK 3: Constraints
------------------------------------------------------------------

Team Member: Person 3
Implementation Location: users/constraints.py

A. BUSINESS CONSTRAINTS CLASS
   - File: users/constraints.py
   - Class: BusinessConstraints
   
   - Order Constraints:
     * MIN_ORDER_AMOUNT = $10.00
     * MAX_ORDER_AMOUNT = $10,000.00
     * MAX_ITEMS_PER_ORDER = 50
   
   - Delivery Constraints:
     * MAX_DELIVERY_TIME_HOURS = 4
     * MIN_DELIVERY_TIME_MINUTES = 30
   
   - User Constraints:
     * MIN_PASSWORD_LENGTH = 8
     * MAX_PENDING_ORDERS_PER_USER = 5
   
   - System Constraints:
     * MAX_ORDERS_PER_HOUR = 100
     * MAX_CONCURRENT_USERS = 500

B. VALIDATION FUNCTIONS
   - validate_order_amount(amount)
     * Validates order against min/max limits
     * Raises ValidationError if out of range
   
   - validate_delivery_time(estimated_time)
     * Ensures delivery time is within valid range
     * Min: 30 minutes from now
     * Max: 4 hours from now
   
   - validate_user_pending_orders(user)
     * Checks if user has too many pending orders
     * Max: 5 pending orders per user
   
   - validate_role_access(user, required_roles)
     * Validates if user has required role
     * Used throughout views for permission checks

C. CONSTRAINT APPLICATION
   - Applied in:
     * orders/views.py - Order creation validation
     * users/views.py - User management validation
     * All CRUD operations check constraints before proceeding

TASK 5: Authentication / Access Control
------------------------------------------------------------------

Team Member: Person 5
Implementation Location: users/models.py, users/views.py, users/serializers.py

A. CUSTOM USER MODEL
   - File: users/models.py
   - Extends: AbstractUser
   - Additional Fields:
     * role (CharField with choices)
     * phone (CharField with regex validation)
     * address (TextField)
     * created_at, updated_at (DateTimeField)
   
   - Role Choices:
     * admin - Full system access
     * manager - Order and user management
     * analyst - Analytics and reports access
     * delivery - Delivery person functions
     * customer - Order placement and tracking

B. AUTHENTICATION SERVICES
   - File: users/serializers.py
   - Serializers:
     * UserSerializer - User data serialization
     * UserRegistrationSerializer - Registration with password confirmation
     * LoginSerializer - Login credentials validation
     * ChangePasswordSerializer - Password change with old password verification

C. AUTHENTICATION VIEWS
   - File: users/views.py
   - Endpoints:
     * RegisterView - POST /api/auth/register/
     * LoginView - POST /api/auth/login/ (returns token)
     * LogoutView - POST /api/auth/logout/
     * UserProfileView - GET/PUT /api/auth/profile/
     * ChangePasswordView - POST /api/auth/change-password/
     * UserListView - GET /api/auth/users/ (role-filtered)
     * UserDetailView - GET/PUT/DELETE /api/auth/users/<id>/
     * update_user_role - POST /api/auth/users/<id>/role/ (admin only)

D. ROLE-BASED ACCESS CONTROL
   - Implemented in all views:
     * validate_role_access(user, required_roles) function
     * Permission checks before CRUD operations
     * Admin has full access
     * Manager can manage orders and some users
     * Analyst can access analytics and reports
     * Delivery persons can only see assigned orders
     * Customers can only see their own orders

E. TOKEN AUTHENTICATION
   - REST Framework Token Authentication
   - Token generated on registration/login
   - Token stored in localStorage (frontend)
   - Token sent in Authorization header for all API calls

TASK 6: Password Protection in Backend
------------------------------------------------------------------

Team Member: Person 6
Implementation Location: backend/settings.py, users/models.py, users/constraints.py

A. DJANGO PASSWORD VALIDATORS
   - File: backend/settings.py
   - AUTH_PASSWORD_VALIDATORS:
     * UserAttributeSimilarityValidator
       - Prevents passwords similar to user attributes
     * MinimumLengthValidator
       - Enforces minimum password length (8 characters)
     * CommonPasswordValidator
       - Prevents common/weak passwords
     * NumericPasswordValidator
       - Prevents all-numeric passwords

B. PASSWORD HASHING
   - Django's built-in password hashing
   - Uses PBKDF2 with SHA256 algorithm
   - Automatic salt generation
   - Passwords never stored in plain text

C. PASSWORD VALIDATION IN CONSTRAINTS
   - File: users/constraints.py
   - BusinessConstraints.MIN_PASSWORD_LENGTH = 8
   - Applied in UserRegistrationSerializer
   - Password confirmation required for registration

D. PASSWORD CHANGE FUNCTIONALITY
   - File: users/views.py
   - ChangePasswordView endpoint
   - Requires old password verification
   - Validates new password against Django validators
   - New password must be confirmed

E. SECURITY MEASURES
   - SECRET_KEY in settings (should be environment variable in production)
   - Token-based authentication (not session-based)
   - HTTPS recommended for production
   - Password change requires old password
   - Password reset endpoint can be added using Django's built-in auth

6. DEPLOYMENT INSTRUCTIONS
===============================================================================

BACKEND DEPLOYMENT
------------------
1. Set environment variables:
   - SECRET_KEY
   - DEBUG=False
   - ALLOWED_HOSTS
   - DATABASE_URL (PostgreSQL recommended for production)

2. Collect static files:
   python manage.py collectstatic

3. Use Gunicorn or uWSGI as WSGI server:
   gunicorn backend.wsgi:application

4. Configure Nginx as reverse proxy

5. Use PostgreSQL instead of SQLite for production

FRONTEND DEPLOYMENT
-------------------
1. Build for production:
   cd frontend
   ng build --prod

2. Deploy dist/ folder to web server
3. Configure Nginx to serve Angular files
4. Update API URL in services to production backend URL
